---
name: Fatal-move consent + neck-reversal guards
description: Consent gate for human certain-death moves and the adjacency-is-not-validity lesson behind 180° reversals.
---

**Rule 1 — consent gate:** A HUMAN-AUTHORED staged move that is certain death may only stage with a branded `FatalMoveConsent`, mintable solely in `confirmFatalMove` (server re-validates fatality + controlling user) and the kill-all suicide paths. Unconsented → fall back to bot move + one-per-turn WS confirmation prompt. Commit stays a pure passthrough (no re-checks at commit time).
**Human-authored = `manual` ONLY** — the one source where the direction is a literal instruction the human gave that HARD-OVERRIDES the bot with nothing arbitrating its safety. Exempt: `bot` (no better alternative to offer) and `waypoint` (goto/near), because a click-target is a weighted vote scored through the heuristic matrix, so the bot's own death-aversion already outvotes it — see [goto-near-weighted-targets.md](goto-near-weighted-targets.md). Prompting for a waypoint would ask the human to confirm a move the BOT picked. The source-agnostic red fatal-move marker (`isStagedMoveFatal`) still flags such a move in the UI. (`queue` was gated while it existed; the premove queue tool has since been removed entirely.)
**Why:** silent fatal submissions killed snakes without user intent; a branded type makes it a compile-time impossibility to bypass the dialog. Scope it to instructions, not influences: gating bot-chosen moves trains the operator to dismiss the dialog.

**Rule 2 — adjacency ≠ validity (now historical; the lesson is permanent):** Never derive a move from a stored plan cell just because it's adjacent to the head. The just-vacated neck (body[1]) is always adjacent and always a 180° death, and a plan-advance tolerance must never HOLD a cell the snake is moving away from — that exact HOLD-retention pattern caused a real in-game death (a queued cell became the neck one turn later). The machinery that enforced this (premove-queue derivation, `isStepBehindAnchor`/`cellBehindAnchor`, the HOLD tolerance) was DELETED along with the premove queue: no current source walks a stored plan cell-by-cell — goto/near pick from the decision engine's candidate moves, which structurally exclude self-collision. Any NEW source that walks a stored plan must re-adopt both guards.

**Tripwire:** a permanent warn logs full state whenever any staged move steps onto the snake's own neck. Tests staging arbitrary moves must avoid genuine reversals or they'll trip it.

**How to apply:** any new move source (new intent mode, automation) that HARD-OVERRIDES the bot with a human-authored direction must route through the consent gate and, if it walks a stored plan, re-adopt the neck guards. A source that merely biases the bot's scoring does not belong in the gate. Never add a second minting site for the consent brand.
